Konstruktor und new: was beim Erzeugen wirklich passiert

Warum diese Lektion? In Lektion 1 hast du new als Zauberwort benutzt: Damit entstehen Objekte, fertig. Klausuraufgaben fragen hier aber gern genauer nach: Welcher Konstruktor feuert bei welchem Aufruf, welche Startwerte hat ein Attribut, wenn der Konstruktor es nicht anfasst, und warum kompiliert auf einmal new Konto() nicht mehr? Nach dieser Lektion kannst du all das beantworten, statt es zu raten.

Abrufübung: Lektion 1, kalt

Zwei Fragen aus dem Gedächtnis, ohne zurückzublättern. Genau dieses Kalterufen macht den Stoff dauerhaft.

Phase für Phase: was new Konto("Kim", 20) anrichtet

Der Aufruf sieht wie ein Befehl aus, ist aber ein dreistufiger Vorgang. Diese Stufen erkennst du in fast jeder Zustandsverfolgungs-Aufgabe wieder:

Die drei Phasen des Erzeugens
  • Platz. Java holt Speicher für ein neues Objekt der Klasse Konto an.ein new = ein neuer Speicherbereich
  • Erstwerte. Jedes Attribut bekommt automatisch einen Nullwert: Zahlen 0 bzw. 0.0, boolean false, Objektreferenzen null.passiert vor allem anderen
  • Konstruktorlauf. Der passende Konstruktor führt seine Zuweisungen aus und überschreibt Erstwerte durch echte Startwerte.Parameter landen in Attributen
Merkkasten · Erstwerte Zwischen Phase 2 und 3 existiert das Objekt mit wertlosen Attributen: kontostand wäre kurz 0.0 und inhaber wäre null. Fasst der Konstruktor ein Attribut nicht an, bleibt genau dieser Nullwert stehen. Genau deshalb kann eine Ausgabe später null lauten, obwohl alles kompiliert.

Phase 3 hat Regeln, denn nicht jeder Block im Klassentext ist ein Konstruktor. Die nächsten zwei Abschnitte liefern die Spielregeln und die Falle dazu.

Die Spielregeln des Konstruktors

Spielregeln
  • Er heißt exakt wie die Klasse.
  • Er hat keinen Rückgabetyp, nicht einmal void.
  • Er läuft automatisch bei jedem new, man ruft ihn nie direkt auf.
  • Eine Klasse darf mehrere Konstruktoren haben, solange sich ihre Parameterlisten unterscheiden. Das heißt Überladung, englisch overloading.

So sieht das bei deinem Konto aus. Kopier die Klasse in den Java-Editor und probier beide Konstruktoren aus:

Konto.java · jetzt mit Überladung 
public class Konto {

    private String inhaber;
    private double kontostand;

    // Konstruktor 1: Inhaber und Startbetrag
    public Konto(String neuerInhaber, double startbetrag) {
        inhaber = neuerInhaber;
        kontostand = startbetrag;
    }

    // Konstruktor 2: nur ein Startbetrag, Inhaber offen
    public Konto(double startbetrag) {
        kontostand = startbetrag;
    }

    public void einzahlen(double betrag) {
        kontostand = kontostand + betrag;
    }

    public String getInhaber() { return inhaber; }
    public double getKontostand() { return kontostand; }
}
Die Falle: Schreibst du für eine Klasse gar keinen Konstruktor, spendiert Java einen unsichtbaren ohne Parameter. Schreibst du aber irgendeinen selbst, ist dieser implizite weg. Hat deine Klasse nur Konto(String, double), dann kompiliert new Konto() nicht mehr, weil kein passender Konstruktor für die leere Klammer existiert. Diese Fehlermeldung siehst du sofort im Java-Editor.
Wie Java den passenden Konstruktor wählt
  • new Konto("Ada", 100) → zwei Werte, String plus Zahl → Konstruktor 1 läuft.Parameterliste passt exakt
  • new Konto(75) → eine Zahl → Konstruktor 2 läuft, inhaber bleibt null.drei Phasen, dann Lauf von Nr. 2
  • new Konto() → kompiliert nicht, weil kein Konstruktor ohne Parameter existiert.impliziter wurde verdrängt

Blick voraus: wenn Parameter wie Attribute heißen

Blick voraus · this Statt neuerInhaber darf ein Parameter auch schlicht inhaber heißen. Dann sind zwei Namen gleich belegt und die Zuweisung braucht this.inhaber = inhaber;: Links vom Punkt steht das Attribut des entstehenden Objekts, rechts davon der Parameter. Ohne this würde die Zeile nur den Parameter auf sich selbst zuweisen, das Attribut bliebe null. Eigene Übungen dazu kommen in Lektion 3.
