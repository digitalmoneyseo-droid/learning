Klasse und Objekt: der Bauplan und seine Exemplare

Warum diese Lektion? Dein LK hat mit der Objektorientierung begonnen, und fast jede Klausuraufgabe der nächsten zwei Jahre fragt dasselbe in Verkleidung: Was ist die Klasse, was ist ein Objekt davon, und was weiß welches Objekt wann? Wer diese Unterscheidung sauber trifft, kann später Konstruktoren, Geheimnisprinzip und Vererbung verstehen. Wer sie schwammig lässt, rutscht bei jeder Folge-Thematik ins Raten.

Zwei Blicke auf dieselbe Sache

Nimm ein Girokonto im echten Leben. Es gibt genau einen Vertragsbauplan: so sieht ein Konto bei deiner Bank aus, welche Daten es hat, was damit geht. Und es gibt Millionen konkreter Konten, die alle nach diesem einen Plan laufen, jedes mit eigenem Stand und eigenem Inhaber. Genau diese zwei Blicke heißen in Java:

Definition

Eine Klasse ist der Bauplan im Programmtext. Sie legt fest, welche Attribute (Zustandsdaten) und welche Methoden (Verhalten) ihre Objekte haben.

Ein Objekt (auch: Instanz, Exemplar) ist ein konkretes Exemplar, das zur Laufzeit mit new erzeugt wird. Es besitzt eigene Attributwerte. [Oracle, „What Is a Class?“]

Die Metapher hat eine Grenze, die Klausuren gerne testen: der Bauplan selbst tut nichts und hält nichts. Nur die erzeugten Objekte tragen Werte und führen Methoden aus. Wer Sätze bildet wie „die Klasse Konto hat 150 Euro“, mischt die beiden Blicke.

Der Bauplan als Code: die Klasse Konto

So sieht der Plan in Java aus. Schreib ihn einmal in den Java-Editor und führe ihn aus, er läuft unverändert:

Konto.java 
public class Konto {

    private String inhaber;
    private double kontostand;

    public Konto(String neuerInhaber, double startbetrag) {
        inhaber = neuerInhaber;
        kontostand = startbetrag;
    }

    public void einzahlen(double betrag) {
        kontostand = kontostand + betrag;
    }

    public void abheben(double betrag) {
        kontostand = kontostand - betrag;
    }

    public String getInhaber() { return inhaber; }
    public double getKontostand() { return kontostand; }
}

Drei Bausteine zählen im Moment mehr als der Rest: Die Zeilen private String inhaber; und private double kontostand; sind die Attribute, der Speicherplatzplan für jedes spätere Objekt. Der Block Konto(...) ist der Konstruktor, die Anlaufstelle beim Erzeugen, er setzt die Startwerte. Und alles, was ein Konto tun kann, steht als Methode darunter: einzahlen, abheben, Werte abfragen. Was der Konstruktor genau macht und warum get...-Methoden diesen Namen tragen, sind eigene Lektionen, dafür brauchst du hier nur die Rollen.

Vom Plan zum Ding: zwei Objekte erzeugen

Der Plan allein rechnet noch nichts. Dieses Testprogramm erzeugt zwei Konten und lässt sie sich unabhängig voneinander bewegen:

Kontotest.java 
public class Kontotest {

    public static void main(String[] args) {
        Konto k1 = new Konto("Mira", 100);
        Konto k2 = new Konto("Ben", 50);

        k1.einzahlen(50);

        System.out.println(k1.getInhaber() + ": " + k1.getKontostand());
        System.out.println(k2.getInhaber() + ": " + k2.getKontostand());
    }
}

// Ausgabe:  Mira: 150.0
//           Ben: 50.0
Schritt für Schritt: was passiert wann?
  • new Konto("Mira", 100) → Objekt 1 entsteht: inhaber=Mira, kontostand=100.0ein new = ein neues Exemplar
  • new Konto("Ben", 50) → Objekt 2 entsteht: inhaber=Ben, kontostand=50.0vom selben Plan, eigener Zustand
  • k1.einzahlen(50) → nur das Objekt hinter k1 rechnet: 100+50=150Aufruf gilt nur fürs angesprochene Objekt
  • k2 wurde nie angefasst: sein Kontostand bleibt 50.0Zustände wohnen getrennt
Häufigster Klausurfehler: Klasse und Objekt in einem Satz vermischen. „Die Klasse Konto hat gerade 150 Euro“ ist falsch, denn nur jedes konkrete Objekt trägt Werte. Gleiches gilt umgekehrt für Aufrufe: k1.einzahlen(50) geht, Konto.einzahlen(50) nicht, weil einzahlen an einem Exemplar hängt, nicht am Bauplan.
